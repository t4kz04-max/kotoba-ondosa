## 0. 全画面共通

### 画面一覧と PRD 機能の対応

| # | 画面 | step（DOMAIN_SPEC §8） | 対応機能 |
|---|---|---|---|
| 1 | スタート画面 | `HOME` | F1 |
| 2 | 言葉・場面の選択画面 | `SCENARIO_SELECT` | F2 |
| 3 | 感覚入力画面 | `INPUT_A` / `INPUT_B` | F3, F5 |
| 3' | 交代画面・公開前画面 | `HANDOFF` / `READY_TO_REVEAL` | F5 |
| 4 | 比較結果画面（最重要） | `COMPARISON` | F4, F6 |
| 5 | 言葉の具体化画面 | `AGREEMENT` | F7, F8 |
| 6 | 完了画面 | `COMPLETE` | F9 |

### 共通要素

- **ヘッダー**：作品名（小さく）と「最初から」ボタン（F10、`RESET`）。「最初から」は確認ダイアログ（「最初からやり直しますか？ 入力した内容は消えます」）を出す。スタート画面では表示しない。
- **進行表示**：「1 / 4」のような数値は使わず、「えらぶ → こたえる → くらべる → ことばにする」の4段階表示で現在位置を示す。ふたりモードの交代画面は「こたえる」に含める。
- **主ボタン**：各画面で次へ進むボタンは1つだけ目立たせる。
- **用語**：「正解」「間違い」「スコア」「点数」「普通」は使わない。
- **言語**：すべて日本語。漢字には中学生が読める範囲を使う。

### やり直しの導線

| 画面 | やり直しの方法 |
|---|---|
| すべて（スタート以外） | ヘッダーの「最初から」→ スタート画面（`RESET`） |
| 比較結果・具体化・完了 | 「ほかの言葉でくらべる」→ 同じモードで選択画面（`RESTART_SAME_MODE`） |
| 具体化 | 「時間を選びなおす」（`REVISE_AGREEMENT`）、「戻る」→ 比較結果 |

比較結果画面から入力画面へは戻らない（PRD §15 の決定事項）。

### 共通のアクセシビリティ

- 画面遷移時に、新しい画面の見出し（`h1`）へフォーカスを移す。
- 情報を色だけで区別しない（A/B はラベル・模様・位置でも区別）。
- 文字と背景のコントラスト比 4.5:1 以上（WCAG 2.1 AA）。
- タップ領域は 44×44px 以上。
- すべての操作をキーボードで行える。フォーカスが見える。
- `prefers-reduced-motion` のときアニメーションを止める（Phase 5）。

### 共通のスマートフォン操作

- 縦向き・片手操作を基本とする。主ボタンは画面下部の親指が届く位置。
- 幅 320px から横スクロールなしで表示する。
- ピンチ操作に依存しない。

## 1. スタート画面（`HOME`）

**目的**：何をするアプリかを1行で伝え、すぐに始めてもらう。

**表示情報**
- 作品名「言葉の温度差」、副題「同じ言葉なのに、同じ意味じゃない。」
- 問いかけ：「あなたの「すぐ」は何分？」（Phase 5A で短くした）
- 一言説明（1〜2行）：「同じ言葉で思いうかべる時間を、相手とくらべてみよう。正解はありません。」

**UI 要素**
- 主ボタン「ひとりで体験する」
- 主ボタン「ふたりで比べる」（1台の端末を交代で使う、と小さく補足）
- 「回答はどこにも保存されません」の注記

**ユーザー操作 → 状態遷移**
- どちらかのボタン → `SELECT_MODE` → 選択画面

**入力エラー**：なし。

**スマートフォン**：2つのボタンを縦に並べ、画面下半分に配置。

**アクセシビリティ**：ボタンのラベルだけで意味が通じるようにする（「ひとりで体験する（架空のサンプルとくらべる）」を補足テキストとして関連付ける）。

**30秒デモ**：0〜3秒。問いかけを読ませ、すぐ「ひとりで体験する」を押す。

## 2. 言葉・場面の選択画面（`SCENARIO_SELECT`）

**目的**：比べる言葉を選び、その言葉が使われる場面を共有する。

**表示情報**
- 見出し「どの言葉でくらべる？」
- 3枚のカード。各カードに：言葉（大きく）、場面の説明（1〜2文。DOMAIN_SPEC §2.2）

**UI 要素**：カード（ボタンとして機能）、「戻る」

**ユーザー操作 → 状態遷移**
- カードを選ぶ → `SELECT_SCENARIO` → 入力画面（A）
- 戻る → `BACK` → スタート

**入力エラー**：なし（選ぶだけ）。

**スマートフォン**：カードを縦に3枚並べる。カード全体がタップ領域。

**アクセシビリティ**：各カードは1つのボタン。アクセシブルな名前は「すぐ行く：友だちと待ち合わせ中…」。

**30秒デモ**：3〜5秒。「すぐ行く」を選ぶ（最初のカードに置く）。

## 3. 感覚入力画面（`INPUT_A` / `INPUT_B`）

**目的**：その言葉が当てはまると感じる時間の **範囲** を、迷わず入力してもらう。

**表示情報**
- 誰の番か：ひとりモード「あなたの感覚」、ふたりモード「Aさんの番」「Bさんの番」
- 言葉と場面（選択画面と同じ文）
- 問い（シナリオの `question`）。例：「メッセージが来てから友だちが着くまで、どのくらいなら『すぐ行く』だと思う？」
- 起点と終点：軸の左端に「メッセージが届いた」、右方向に「→ 友だちが着く」
- 現在の範囲の文章表示：未入力なら「まだ選んでいません」、入力後は「5分〜15分」
- プレビュー：入力済みの範囲を、比較画面と同じ線形の時間軸上に表示する
- **上限の注記**：「このアプリでは60分までで答えます。60分より長いと感じる人もいます。」（最大値は比較のための範囲で、言葉の意味の上限ではない。DOMAIN_SPEC §2.2）

**UI 要素**
- 「早くて」（範囲の始まり）：スライダー＋数値入力
- 「遅くて」（範囲の終わり）：スライダー＋数値入力
- 主ボタン「これで決定」
- 「戻る」

**入力の仕様**
- **初期状態は未入力**（`draft = { start: null, end: null }`）。スライダーの初期位置は回答として扱わない。
  - 未入力の間、スライダーのつまみは「未選択」と分かる表示にする（例：つまみを薄く表示し、値の欄は「—」）。具体的な見た目は Phase 4〜5 で決める。
  - ユーザーがスライダーを操作する、または数値を入力すると、その端点が入力済みになる（`SET_DRAFT`）。
- 両方の端点が入力済みで、早くて ≤ 遅くて のときだけ「これで決定」を押せる（`selectInputView` の `canSubmit`）。確定は `SUBMIT_ANSWER` で、未入力・不正な範囲はセッションが拒否する。
- 刻みはシナリオの `inputStepSeconds`（すぐ行く：1分、ちょっと待って：10秒、あとでやる：5分）。
- 数値入力の単位：すぐ行く「分」、ちょっと待って「分・秒」、あとでやる「時間・分」。入力値は秒に換算して `SET_DRAFT` する。
- 「早くて」と「遅くて」は独立して動かす（もう一方を自動では動かさない）。逆転した場合はエラーとして理由を表示し、確定できない。
- スライダーは刻み（`inputStepSeconds`）で大まかに、数値入力は 1 秒（あとでやるは 1 分）単位で正確に調整する。12時間を1秒刻みのスライダーで操作させない。
- スライダーの位置が未入力の初期位置と同じ値（0）を選ぶときは、数値で「0」を入力する（画面に案内を表示）。
- 早くて ＝ 遅くて（長さ0）も有効。表示は「ちょうど5分」。

**ユーザー操作 → 状態遷移**
- 「これで決定」→ `SUBMIT_ANSWER`
  - ひとりモード → 比較結果画面
  - ふたりモード A → 交代画面（`HANDOFF`）
  - ふたりモード B → 公開前画面（`READY_TO_REVEAL`）
- 戻る（`BACK`）：A は選択画面へ（入力は破棄）。B は交代画面へ（**A の入力画面には戻れない**）。

**入力エラーへの対応**

（Phase 7）「3分75秒」のように下の単位がくり上がる入力は、エラーにせず 4分15秒として扱い、その欄の下に「3分75秒は、4分15秒として扱います。」と表示する。小数・負の数（「1.5」「-1」）は数字以外としてエラーにする。

| 状況 | 対応 |
|---|---|
| 片方だけ入力 | 「これで決定」を押せない。「『早くて』と『遅くて』の両方を選んでね」と表示 |
| 数値入力で 早くて > 遅くて | 「これで決定」を押せない。「『早くて』は『遅くて』以下にしてね」と表示 |
| 数値入力で上限超過・負の値 | 入力欄の下に「0〜60分で入力してね」と表示し、確定できない |
| 刻みに合わない数値 | 最も近い刻みの値に合わせて表示する（UI 側の丸め。ドメインは任意の整数秒を受け付ける） |

エラー文は入力欄と `aria-describedby` で関連付ける。

**スマートフォン**
- スライダーは画面幅いっぱい。つまみは 44px 以上。
- 数値入力は `inputmode="numeric"` で数字キーボードを出す。
- 2つの入力を縦に並べ、それぞれにラベルと現在値を大きく表示する。

**アクセシビリティ**
- ネイティブの `<input type="range">` と `<input>`（数値）を使う。
- `aria-label`：「早くて（範囲の始まり）」「遅くて（範囲の終わり）」。
- `aria-valuetext`：「5分」のような読める値。未入力のときは「未選択」。
- 範囲の文章表示を `aria-live="polite"` で読み上げる。

**30秒デモ**：5〜15秒。スライダーで「0分〜5分」を選んで決定。

## 3'. 交代画面・公開前画面（ふたりモードのみ）

### 交代画面（`HANDOFF`）

**目的**：A の回答を B に見せずに端末を渡す。

**表示情報**：「Aさんの回答をかくしました。端末をBさんに渡してください。」「Bさんは、Aさんの答えを聞かずに答えてね。」
**表示しないもの**：A の範囲・軸・プレビュー（一切出さない。画面に A の回答を渡さない）。
**UI 要素**：主ボタン「Bさんです。はじめる」
**操作**：ボタン → `START_INPUT_B` → 入力画面（B）。「最初から」以外の戻る操作はない。
**スマートフォン**：ボタンを画面中央〜下部に大きく。A が誤って押さないよう、ボタンのラベルに「Bさん」を明記。
**アクセシビリティ**：見出しにフォーカス。

### 公開前画面（`READY_TO_REVEAL`）

**目的**：2人がそろって画面を見てから結果を開く（驚きを共有する瞬間をつくる）。

**表示情報**：「2人の答えがそろいました」「結果はまだかくれています。2人で画面を見られるようにしてから、公開してね。」（Phase 5A：比較結果の公開演出の待機状態を兼ねる）
**表示しないもの**：A・B の範囲（`selectComparisonView` はこの画面では値を返さない）。
**UI 要素**：主ボタン「2人の感覚を公開する」
**操作**：ボタン → `REVEAL` → 比較結果画面

## 4. 比較結果画面（`COMPARISON`）【最重要画面】

**目的**：2人の範囲を同じ時間軸に重ね、どこが共通でどこが違うかを **一目で** 分かるようにする。判定はしない。

### 4.1 情報の優先順位（上から順に配置）

1. **見出し（関係を一言で）**：`description.headline`。例「2人の『すぐ行く』は重なりませんでした」
2. **時間軸の図**（下記 4.2）
3. **事実の説明**：`description.details`。共通範囲、空白、中心値の差。
4. **うながし**：`description.prompt`
5. **主ボタン**「具体的な言葉にする」（Phase 5B：画面下に固定し、スクロールしなくても常に押せるようにした）
6. （ひとりモード）サンプル切り替えと架空注記（Phase 5B：図のすぐ下に移動。架空注記は図の直下のまま）
7. 補助ボタン「ほかの言葉でくらべる」

### 4.2 時間軸の図（SVG）

```
 すぐ行く   メッセージが届いた →→→→→→→→→→→→→→→→→→→→→→→ 友だちが着く
            0     10分    20分    30分    40分    50分    60分
            |-------|-------|-------|-------|-------|-------|
 あなた     [■■■]                                               0分〜5分
 ソラ(架空)             [▨▨▨▨▨▨▨▨▨▨▨▨]                           15分〜30分
                ↔ 10分のひらき
```

- **線形の時間軸**：座標は経過時間に比例する（DOMAIN_SPEC §6）。目盛りは `generateTicks` で間引くが、比例関係は変えない。
- **全体表示**（初期値）：表示範囲 `[0, maxSeconds]`。
- **拡大表示**：`computeZoomView` で、A・B の両方の範囲が収まる表示範囲（範囲全体の長さの 15% ずつ余白、最小 30 秒、`[0, maxSeconds]` 内）を計算する。表示範囲を変えるだけなので線形性は保たれる。
- 「全体表示」「拡大表示」の切り替えボタン（`aria-pressed`）を置き、「拡大表示中：0分〜3分41秒 を表示しています（全体は 0分〜30分）」のように現在の表示範囲を文章で明記する。2人の範囲が広く拡大しても全体と同じになる場合は、その旨を表示する。
- 1本の共通の横軸に、A の帯（上段）と B の帯（下段）を並べる。
- 軸の左に起点、右に終点を表示する。
- 各帯の左に名前ラベル、右に範囲の文章（「0分〜5分」）。
- A と B は色に加えて **塗りの模様**（ベタ／斜線）でも区別する。
- **共通範囲**：2本の帯をまたぐ縦の帯で強調し、「共通：3分〜15分」とラベルを付ける。
- **空白（gap）**：2本の帯の間に両矢印と「10分のひらき」を表示する。
- **接触（touch）**：接している1点に縦線と「5分で重なっている」のラベル。
- **短い範囲・長さ0の範囲**：線形軸では「ちょっと待って」の「10秒〜30秒」などがとても短く描かれる。**最小描画幅による拡大は行わない**（実際の幅を不正確にするため）。全体表示で4px未満の帯がある場合は「拡大表示で見やすくなります」と案内する。長さ0の範囲はひし形のマーカーで位置を示す（幅は持たせない）。
- **包含**：共通範囲の強調で表現する（内側の範囲がまるごと強調される）。
- 中心値は図に描かない。中心値の差は文章で示す。

### 4.3 relation ごとの見せ方

| relation | 見出し（例） | 図で強調するもの |
|---|---|---|
| identical | ぴったり同じでした | 共通範囲＝両方の帯全体 |
| a-contains-b / b-contains-a | すっぽり入っています | 共通範囲（内側の範囲） |
| overlap | 一部だけ重なっています | 共通範囲の縦帯 |
| touch | 1点だけで重なっています | 接点の縦線 |
| gap | 重なりませんでした | 空白の両矢印と長さ |

### 4.4 ひとりモードの追加要素

- サンプル切り替え：「ほかのサンプルとくらべる」として3件の名前ボタン（選択中を明示）。切り替えると（`SELECT_SAMPLE`）図・見出し・説明文が更新される。
- 架空注記（常時表示、図の直下）：「このサンプルは説明用に作った架空の回答です。実際の調査結果ではありません。」

### 4.5 状態遷移

- 「具体的な言葉にする」→ `START_AGREEMENT` → 具体化画面
- サンプル切り替え → `SELECT_SAMPLE` → 同じ画面
- 「ほかの言葉でくらべる」→ `RESTART_SAME_MODE` → 選択画面
- 入力画面へ戻る操作は設けない（ふたりモードで相手の回答を知った後の再入力になるため）。

### 4.6 入力エラー

なし。比較計算が例外を投げた場合（プログラムの誤り）は、エラー表示と「最初から」ボタンを出す（TECH_SPEC §7）。

### 4.7 スマートフォン

- 図は画面幅いっぱい。目盛り数は画面幅に応じて `generateTicks` の `maxTicks` を変える（例：320px で 4、1280px で 7）。
- 名前ラベルと範囲の文章は、図の外（帯の上）に配置して文字を小さくしすぎない。
- 図・見出し・主ボタンが、375×667px の画面でスクロールなし（または最小限のスクロール）に収まるようにする。

### 4.8 アクセシビリティ

- SVG に `role="img"` と、見出し＋details を結合した `aria-label`（または `<title>`／`<desc>`）を付ける。
- 図と同じ情報を文章（details）でも必ず表示する。
- 見出しを `h1` とし、画面表示時にフォーカスする。

### 4.9 30秒デモでの見せ方

15〜25秒。帯が同じ軸に並び、離れている（gap）ことと「10分のひらき」が一目で分かる結果を見せる。ここが「違いに驚く」瞬間。

## 5. 言葉の具体化画面（`AGREEMENT`）

**目的**：「違いがある」で終わらせず、2人が共有できる具体的な言葉を **人が選び、実行できるか確かめて** 作る。

**解釈と実行可能性の区別**：比較結果は「どう感じるか（解釈）」であり、「実際にその時間でできるか（実行可能性）」とは別である。候補は解釈から出した手がかりにすぎない。

**表示情報**
- 見出し「『すぐ行く』を、具体的な言葉にしよう」
- 小さな比較図（比較画面の図の縮小版）
- 手がかり（候補）：`candidates` をボタンで表示。見出しは「2人の感じ方からの手がかり」。ラベルは根拠つき：
  - 「共通範囲の終わり：15分」
  - 「Aさんの範囲の終わり：5分」／ひとりモードは「あなたの範囲の終わり」
  - 「Bさんの範囲の終わり：30分」／ひとりモードは「ソラ（架空）の範囲の終わり」
- 注記：「手がかりは、2人が『当てはまる』と感じた時間です。その時間で本当にできるかは、別に確かめよう。」
- 完成する文のプレビュー：`text`（例「今から10分以内に着くね」）。未選択時は「時間を選ぶと、ここに言葉ができます」

**UI 要素**
- 候補ボタン（0〜3個。0個のときは「ほかの時間」だけを表示）
- 「ほかの時間」：スライダー＋数値入力（入力画面と同じ部品、刻みも同じ。1秒以上・上限以下）
- 実行可能性の確認（時間を選んだ後に表示）：
  - 問い：`feasibilityQuestion`（例「今から10分以内に、本当に着けそう？」）
  - ふたりモード：A・B それぞれに「この時間でできる／待てる」のチェックと「OK」ボタン。チェックしないと「OK」を押せない
  - ひとりモード：「この時間でできる」のチェックと「この言葉にする」ボタン
- 「時間を選びなおす」ボタン
- 「戻る」（比較画面へ）

**ユーザー操作 → 状態遷移**
- 候補または「ほかの時間」で時間を選ぶ → `CHOOSE_AGREEMENT_TIME` → プレビュー更新。それまでの承認はリセット
- チェック＋「OK」→ `APPROVE_AGREEMENT { participant, feasibilityConfirmed: true }`
  - ふたりモード：A・B の両方がそろうと完了画面。押したボタンは「Aさん OK 済み」に変わる
  - ひとりモード：1回で完了画面
- 「時間を選びなおす」→ `REVISE_AGREEMENT` → 時間未選択に戻る
- 戻る → `BACK` → 比較画面（選択と承認はリセット）

**入力エラーへの対応**
- 時間未選択では確認エリアを表示しない（セッションも `agreement-time-not-chosen` で拒否）。
- 実行可能性のチェックなしでは承認できない（セッションも `feasibility-not-confirmed` で拒否）。
- 自動で時間を決定しない。候補は最初どれも選ばれていない。

**スマートフォン**
- 候補ボタンは縦に並べ、全幅。
- 確認エリアは A・B を縦に並べ、それぞれチェックと OK を大きく表示する。

**アクセシビリティ**
- 候補ボタン群はネイティブのラジオボタンをボタン風に表示する。
- プレビュー文は `aria-live="polite"`。
- 確認のチェックはネイティブの `<input type="checkbox">`。承認済みは文章でも示す。

**30秒デモ**：25〜30秒。「あなたの範囲の終わり：5分」と「ソラの範囲の終わり：30分」を見比べ、「ほかの時間」で 10分 を選ぶ。「今から10分以内に、本当に着けそう？」にチェックして「今から10分以内に着くね」を完成させる。

### 5.1 Phase 6B での改善

- 冒頭に「感じ方が違っていても、実際にできる時間を話し合って決められます。」。範囲が重なっていれば「重なっていても、それだけで約束になるわけではありません」、重なっていなければ「重なっていなくても、話し合えば決められます」と添える（重なり＝合意、重ならない＝合意できない、と扱わない）。
- 候補の根拠：「2人に共通する範囲の終わり」「Aさんが選んだ範囲の終わり」と、その計算のもとになった範囲（例「2人とも当てはまると感じた 5分〜10分 の、いちばん遅い時間」）。共通範囲がないときは共通範囲の候補を出さない。候補は既存どおり範囲の終わりだけ（文が「◯以内」の形のため。DOMAIN_SPEC §7.2）。
- 完成文のプレビュー：「「すぐ行く」を具体的に言うと」「「今から10分以内に着くね」」と、「いつ：今から10分以内」「何をする：着く」。時間の数えはじめ（例「メッセージが届いたときから」）は文に含まれないので、部品とは別の注記にする。
- 確認：「確かめる言葉「今から10分以内に着くね」」を見せ、A・B が **同じ文** をそれぞれ確認する。チェックの文は「この言葉のとおりに、実際にできる（待てる）」。言う人は「できるか」、聞く人は「待てるか」を考える、と説明する（A・B の役割は固定しない。既存仕様どおり）。
- 状態の表示：「Aさん：確認しました」（取り消すボタン付き）／「Bさん：まだ確認していません」。片方だけのときは「Bさんの確認を待っています。2人がそろうと完成します。」
- 確認済みの人がいる状態で時間を変えると「時間が変わったので、確認はリセットされました。」と知らせる。
- 確認カードの下に「この時間ではむずかしいときは、別の時間を話し合って選びなおせます。」と「時間を選びなおす」。押すと時間の選択に戻り、「時間を選ぶ」の見出しにフォーカスが移る。
- ひとりモードのボタンは「この言い方にする」。「相手が了承したことにはなりません」と表示する。

## 6. 完了画面（`COMPLETE`）

**Phase 6B**：見出しは、ふたりモードで2人とも確認したときだけ「ことばが、約束になった。」。ひとりモードは「具体的な言い方を考えられた。」とし、「あなたが考えた具体的な言い方」と表示する（架空の相手との合意に見せない）。完成文の下に「いつ」「何をする」を表示する。


**目的**：作った言葉を確認し、体験を締めくくる。

**表示情報**
- 見出し「ことばが、約束になった。」
- 完成した文（大きく）：「今から10分以内に着くね」
- 元の言葉との対比：「すぐ行く」→「今から10分以内に着くね」
- 2人の範囲（文章で）
- ふたりモード：「Aさん・Bさんが、この時間でできることを確認しました」
- ひとりモード：「今回の相手は架空のサンプルです。本当の相手と使うときは、相手にも確認しよう。」
- 締めの一言：「曖昧な言葉が悪いわけではありません。大事なときは、具体的に言ってみよう。」

**UI 要素**
- 主ボタン「ほかの言葉でくらべる」→ `RESTART_SAME_MODE` → 同じモードのまま選択画面
- 補助ボタン「最初から」→ `RESET` → スタート
- 「この言葉をコピー」：クリップボードにコピーし、結果（コピーしました／できませんでした）を `aria-live` で知らせる

**入力エラー**：なし。

**スマートフォン**：完成した文を画面中央に大きく表示（スクリーンショットで共有しやすい）。

**アクセシビリティ**：見出しにフォーカス。完成した文はテキストとして選択可能。

**30秒デモ**：30秒時点で完成した文を映して終える。

## 7. 場面を変えて比べる（Phase 6A）

ひとり・ふたりモードとは独立した体験。仕様の目的は PRD §16、計算は DOMAIN_SPEC §12。

**流れ**：スタート →「場面を変えて比べる」→ 場面①の入力 → 場面②の入力 → 場面③の入力 → 結果 →「もう一度試す」（場面①から）または「スタートに戻る」

**進行表示**：「場面① → 場面② → 場面③ → くらべる」（ヘッダーの「最初から」はいつでも使える）

### 7.1 入力画面（3回）

- バッジ「場面①（3つのうち1つめ）」、言葉（「すぐ行く」など）、場面と問い（「「すぐ行く」と伝えてから動き出すまで、何分後から何分後までが自然だと思う？」）。
- 入力欄・エラー・プレビューは既存の入力画面と同じ部品（`RangeInputPanel`：早くて／遅くて、0分にする、欄ごとのエラー、未入力の表示）。上限は30分。
- ほかの場面の回答は表示しない。
- 主ボタン：場面①②は「これで決定して次へ」、場面③は「これで決定してくらべる」。「戻る」は前の場面へ（その場面の回答が戻る）、場面①ではスタートへ。

### 7.2 結果画面

1. 「場面を変えて比べる」、見出し（同じ／違いました）
2. 図：3段（① 塗り・② 横線・③ 点）、各段の名前と範囲、共通部分の縦帯（1点なら縦線）、全体表示／拡大表示、「3つすべてに共通する時間：◯」
3. 「わかったこと」：説明文と、場面ごとの回答の一覧
4. うながしの文
5. 主ボタン「もう一度試す」、補助ボタン「スタートに戻る」

**アクセシビリティ**：見出しにフォーカス。図は `role="img"` と説明文の `aria-label`。場面は色に加えて丸数字・線種・名前で区別する。
