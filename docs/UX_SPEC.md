# UX_SPEC.md

# 言葉の温度差：画面・操作・体験仕様

この文書は **情報設計と操作設計** を定める。色・フォント・装飾・アニメーションなどの見た目は Phase 4（Gemini Canvas による試作）で検討し、Phase 5 で実装する。

関連文書：[PRD.md](PRD.md) / [DOMAIN_SPEC.md](DOMAIN_SPEC.md) / [TECH_SPEC.md](TECH_SPEC.md)

---

## 0. 全画面共通

### 画面一覧と PRD 機能の対応

| # | 画面 | step（DOMAIN_SPEC §7） | 対応機能 |
|---|---|---|---|
| 1 | スタート画面 | `start` | F1 |
| 2 | 言葉・場面の選択画面 | `select` | F2 |
| 3 | 感覚入力画面 | `input-a` / `input-b` | F3, F5 |
| 3' | 交代画面・公開前画面 | `handoff-to-b` / `handoff-reveal` | F5 |
| 4 | 比較結果画面（最重要） | `compare` | F4, F6 |
| 5 | 言葉の具体化画面 | `clarify` | F7, F8 |
| 6 | 完了画面 | `done` | F9 |

### 共通要素

- **ヘッダー**：作品名（小さく）と「最初から」ボタン（F10）。「最初から」は確認ダイアログ（「最初からやり直しますか？ 入力した内容は消えます」）を出す。スタート画面では表示しない。
- **進行表示**：「1 / 4」のような数値は使わず、「えらぶ → こたえる → くらべる → ことばにする」の4段階表示で現在位置を示す。ふたりモードの交代画面は「こたえる」に含める。
- **主ボタン**：各画面で次へ進むボタンは1つだけ目立たせる。
- **用語**：「正解」「間違い」「スコア」「点数」「普通」は使わない。
- **言語**：すべて日本語。漢字には中学生が読める範囲を使う。

### 共通のアクセシビリティ

- 画面遷移時に、新しい画面の見出し（`h1`）へフォーカスを移す。
- 情報を色だけで区別しない（A/B はラベル・模様・位置でも区別）。
- 文字と背景のコントラスト比 4.5:1 以上（WCAG 2.1 AA）。
- タップ領域は 44×44px 以上。
- すべての操作をキーボードで行える。フォーカスが見える。
- `prefers-reduced-motion` のときアニメーションを止める（Phase 5）。

### 共通のスマートフォン操作

- 縦向き・片手操作を基本とする。主ボタンは画面下部の親指が届く位置。
- 幅 320px から横スクロールなしで表示する。
- ピンチ操作に依存しない。

## 1. スタート画面（`start`）

**目的**：何をするアプリかを1行で伝え、すぐに始めてもらう。

**表示情報**
- 作品名「言葉の温度差」、副題「同じ言葉なのに、同じ意味じゃない。」
- 問いかけ：「あなたの『すぐ行く』は、何分後？」
- 一言説明（1〜2行）：「同じ言葉で思いうかべる時間を、相手とくらべてみよう。正解はありません。」

**UI 要素**
- 主ボタン「ひとりで試す」
- 主ボタン「ふたりで試す」（1台の端末を交代で使う、と小さく補足）
- 「回答はどこにも保存されません」の注記

**ユーザー操作 → 状態遷移**
- どちらかのボタン → `choose-mode` → 選択画面

**入力エラー**：なし。

**スマートフォン**：2つのボタンを縦に並べ、画面下半分に配置。

**アクセシビリティ**：ボタンのラベルだけで意味が通じるようにする（「ひとりで試す（架空のサンプルとくらべる）」を補足テキストとして関連付ける）。

**30秒デモ**：0〜3秒。問いかけを読ませ、すぐ「ひとりで試す」を押す。

## 2. 言葉・場面の選択画面（`select`）

**目的**：比べる言葉を選び、その言葉が使われる場面を共有する。

**表示情報**
- 見出し「どの言葉でくらべる？」
- 3枚のカード。各カードに：言葉（大きく）、場面の説明（1〜2文）

| 言葉 | 場面の説明（DOMAIN_SPEC §2.2） |
|---|---|
| すぐ行く | 友だちと待ち合わせ中。先に着いたあなたに、友だちから「すぐ行く」とメッセージが来た。 |
| ちょっと待って | 家の人に「ちょっと来て」と呼ばれて、「ちょっと待って」と返事をした。 |
| あとでやる | 家の人に「宿題やったの？」と聞かれて、「あとでやる」と答えた。 |

**UI 要素**：カード（ボタンとして機能）、「戻る」

**ユーザー操作 → 状態遷移**
- カードを選ぶ → `choose-expression` → 入力画面（A）
- 戻る → スタート

**入力エラー**：なし（選ぶだけ）。

**スマートフォン**：カードを縦に3枚並べる。カード全体がタップ領域。

**アクセシビリティ**：各カードは1つのボタン。アクセシブルな名前は「すぐ行く：友だちと待ち合わせ中…」。

**30秒デモ**：3〜5秒。「すぐ行く」を選ぶ（最初のカードに置く）。

## 3. 感覚入力画面（`input-a` / `input-b`）

**目的**：その言葉が当てはまると感じる時間の **範囲** を、迷わず入力してもらう。

**表示情報**
- 誰の番か：ひとりモード「あなたの感覚」、ふたりモード「Aさんの番」「Bさんの番」
- 言葉と場面（選択画面と同じ文）
- 問い（言葉ごと）：
  - すぐ行く：「メッセージが来てから友だちが着くまで、どのくらいなら『すぐ行く』だと思う？」
  - ちょっと待って：「『ちょっと待って』と言ってから行くまで、どのくらいなら『ちょっと』だと思う？」
  - あとでやる：「『あとでやる』と答えてから宿題を始めるまで、どのくらいなら『あとで』だと思う？」
- 起点と終点の表示：軸の左端に「メッセージが届いた」、右方向に「→ 友だちが着く」
- 現在の範囲の文章表示：「5分〜15分」
- プレビュー：自分の範囲を軸上に表示する（比較画面と同じ軸の形）

**UI 要素**
- スライダー「早くて」（範囲の始まり）
- スライダー「遅くて」（範囲の終わり）
- 各スライダーの横に −／＋ ボタン（1目盛りずつ動かす）
- 主ボタン「これで決定」
- 「戻る」

**スライダーの仕様**
- 値は言葉ごとの `stops`（11点、DOMAIN_SPEC §2.3）の上だけを動く。
- 初期値：早くて＝最小（0）、遅くて＝最大。「つまみを動かして、範囲をせばめてね」と表示する。
  - 理由：中間の値を初期値にすると、その値に回答が引きずられる（アンカリング）ため。全範囲を初期値とし、ユーザーが自分で狭める。
- 「早くて」を「遅くて」より後ろに動かすと、「遅くて」も一緒に動く（逆も同様）。常に 早くて ≤ 遅くて を保つ。
- 早くて ＝ 遅くて（幅0）も有効。表示は「ちょうど5分」。

**ユーザー操作 → 状態遷移**
- 「これで決定」→ `submit-range`
  - ひとりモード → 比較結果画面
  - ふたりモード A → 交代画面（`handoff-to-b`）
  - ふたりモード B → 公開前画面（`handoff-reveal`）
- 戻る：A は選択画面へ（入力は破棄）。B は交代画面へ（**A の入力画面には戻れない**）。

**入力エラーへの対応**
- UI の仕組みで不正値（逆転・範囲外・目盛り外）が作れないため、エラー表示は原則発生しない。
- 全範囲（0〜最大）のまま決定しようとした場合：送信は許可するが、決定前に一度だけ「最初の全部の範囲のままです。このままでいい？」と確認を出す（「このままでいい」「動かす」）。全範囲も有効な回答だが、操作に気づいていない可能性があるため。

**スマートフォン**
- スライダーは画面幅いっぱい。つまみは 44px 以上。
- 2つのスライダーを縦に並べ、それぞれにラベルと現在値を大きく表示する。
- −／＋ ボタンで細かい調整ができる（指でつまみを正確に止めにくい場合のため）。

**アクセシビリティ**
- ネイティブの `<input type="range">` を2つ使う（独自のドラッグ部品にしない）。
- `aria-label`：「早くて（範囲の始まり）」「遅くて（範囲の終わり）」。
- `aria-valuetext`：「5分」のような読める値（秒数ではなく）。値は stops のインデックスで持つため、`aria-valuetext` は必須。
- 矢印キーで1目盛り、Home/End で端に移動。
- 範囲の文章表示（「5分〜15分」）を `aria-live="polite"` で読み上げる。

**30秒デモ**：5〜15秒。「早くて」を少し、「遅くて」を大きく動かして「0分〜5分」などを決定。

## 3'. 交代画面・公開前画面（ふたりモードのみ）

### 交代画面（`handoff-to-b`）

**目的**：A の回答を B に見せずに端末を渡す。

**表示情報**：「Aさんの回答をかくしました。端末をBさんに渡してください。」「Bさんは、Aさんの答えを聞かずに答えてね。」
**表示しないもの**：A の範囲・軸・プレビュー（一切出さない）。
**UI 要素**：主ボタン「Bさんです。はじめる」
**操作**：ボタン → `continue` → 入力画面（B）。「最初から」以外の戻る操作はない。
**スマートフォン**：ボタンを画面中央〜下部に大きく。A が誤って押さないよう、ボタンのラベルに「Bさん」を明記。
**アクセシビリティ**：見出しにフォーカス。

### 公開前画面（`handoff-reveal`）

**目的**：2人がそろって画面を見てから結果を開く（驚きを共有する瞬間をつくる）。

**表示情報**：「2人とも答えました。2人で画面を見てね。」
**表示しないもの**：A・B の範囲。
**UI 要素**：主ボタン「2人でくらべる」
**操作**：ボタン → `continue` → 比較結果画面

## 4. 比較結果画面（`compare`）【最重要画面】

**目的**：2人の範囲を同じ時間軸に重ね、どこが共通でどこが違うかを **一目で** 分かるようにする。判定はしない。

### 4.1 情報の優先順位（上から順に配置）

1. **見出し（関係を一言で）**：`describeComparison` の headline。例「2人の『すぐ行く』は重なりませんでした」
2. **時間軸の図**（下記 4.2）
3. **事実の説明**：details（1〜3文）。共通範囲、空白、中心値の差。
4. **うながし**：prompt「同じ言葉でも、思い浮かべる時間はちがうことがあります。具体的な時間にしてみましょう。」
5. **主ボタン**「具体的な言葉にする」
6. （ひとりモード）サンプル切り替えと架空注記

### 4.2 時間軸の図（SVG）

```
 すぐ行く   メッセージが届いた →→→→→→→→→→→→→→ 友だちが着く
            0   1分  2分  3分  5分  10分 15分 20分 30分 45分 60分
            |----|----|----|----|----|----|----|----|----|----|
 あなた     [■■■■■■■■■■■■■■■]                                      0分〜5分
 ソラ(架空)                          [▨▨▨▨▨▨▨▨▨▨]                  15分〜30分
                                  ↔ 10分のひらき
```

重なりがある場合：

```
            |----|----|----|----|----|----|----|----|----|----|
 Aさん      [■■■■■■■■■■■■■■■■■■■■■■■■■]
 Bさん                [▨▨▨▨▨▨▨▨▨▨▨▨▨▨▨▨▨▨▨▨▨]
                      ┆ 共通: 3分〜15分 ┆        ← 2本の帯をまたぐ縦の帯で強調
```

- **1本の共通の横軸**に、A の帯（上段）と B の帯（下段）を並べる。軸は言葉の stops を等間隔に並べた非線形軸（DOMAIN_SPEC §8）。
- 軸の左に起点（「メッセージが届いた」）、右に終点（「友だちが着く」）を表示する。
- 各帯の左に名前ラベル、右に範囲の文章（「0分〜5分」）。
- A と B は色に加えて **塗りの模様**（ベタ／斜線）でも区別する。
- **共通範囲**：2本の帯をまたぐ縦の帯で強調し、「共通：3分〜15分」とラベルを付ける。
- **空白（gap）**：2本の帯の間に両矢印と「10分のひらき」を表示する。
- **接触（touch）**：接している1点に縦線と「5分で接している」のラベル。
- **幅0の範囲**：短い線ではなく、目立つ点（ひし形など）で描く。
- **包含**：共通範囲の強調で表現する（内側の範囲がまるごと強調される）。
- 中心値は図に描かない（非線形軸では見た目の中心と一致しないため。DOMAIN_SPEC §8）。中心値の差は文章で示す。
- 目盛りの下に小さく「目盛りの間隔は等しくありません」と注記する。

### 4.3 relation ごとの見せ方

| relation | 見出し（例） | 図で強調するもの |
|---|---|---|
| identical | ぴったり同じでした | 共通範囲＝両方の帯全体 |
| a-contains-b / b-contains-a | すっぽり入っています | 共通範囲（内側の範囲） |
| overlap | 一部だけ重なっています | 共通範囲の縦帯 |
| touch | 1点だけで接しています | 接点の縦線 |
| gap | 重なりませんでした | 空白の両矢印と長さ |

### 4.4 ひとりモードの追加要素

- サンプル切り替え：「ほかのサンプルとくらべる」として3件の名前ボタン（選択中を明示）。切り替えると図・見出し・説明文が更新される。
- 架空注記（常時表示、図の直下）：「このサンプルは説明用に作った架空の回答です。実際の調査結果ではありません。」

### 4.5 状態遷移

- 「具体的な言葉にする」→ `continue` → 具体化画面
- サンプル切り替え → `choose-sample` → 同じ画面
- 戻る操作は設けない（入力画面に戻すとふたりモードで再入力時に相手の回答が見えた状態になるため）。やり直しは「最初から」。

### 4.6 入力エラー

なし。比較計算が例外を投げた場合（プログラムの誤り）は、エラー表示と「最初から」ボタンを出す（TECH_SPEC §7）。

### 4.7 スマートフォン

- 図は画面幅いっぱい。目盛りラベルが重なる場合は、偶数番目のラベルを省略する（0 と最大値は必ず表示）。
- 名前ラベルと範囲の文章は、図の外（帯の上）に配置して文字を小さくしすぎない。
- 図・見出し・主ボタンが、375×667px の画面でスクロールなし（または最小限のスクロール）に収まるようにする。

### 4.8 アクセシビリティ

- SVG に `role="img"` と、見出し＋details を結合した `aria-label`（または `<title>`／`<desc>`）を付ける。
- 図と同じ情報を文章（details）でも必ず表示する。図を見なくても内容が分かる。
- 見出しを `h1` とし、画面表示時にフォーカスする（スクリーンリーダーで最初に結果が読まれる）。

### 4.9 30秒デモでの見せ方

15〜25秒。帯が同じ軸に並び、離れている（gap）ことと「10分のひらき」が一目で分かる結果を見せる。ここが「違いに驚く」瞬間。

## 5. 言葉の具体化画面（`clarify`）

**目的**：「違いがある」で終わらせず、2人が共有できる具体的な言葉を **人が選んで** 作る。

**表示情報**
- 見出し「『すぐ行く』を、具体的な言葉にしよう」
- 小さな比較図（比較画面の図の縮小版。共通範囲・空白も表示）
- 手がかり（候補）：`clarifyCandidates` の結果をボタンで表示。ラベルは根拠つき：
  - 「共通範囲の終わり：15分」
  - 「Aさんの範囲の終わり：5分」／ひとりモードは「あなたの範囲の終わり」
  - 「Bさんの範囲の終わり：30分」／ひとりモードは「ソラ（架空）の範囲の終わり」
- 説明（1行）：「どれにするかは2人で決めてね。ほかの時間も選べます。」
- 完成する文のプレビュー：「10分以内に行くね」（未選択時は「時間を選ぶと、ここに言葉ができます」）

**UI 要素**
- 候補ボタン（0〜3個。0個のときは「ほかの時間」だけを表示）
- 「ほかの時間」：stops（0を除く）から選ぶセレクト
- 確認エリア（時間を選んだ後に表示）
  - ふたりモード：「Aさん OK」「Bさん OK」の2ボタン、「変えたい」ボタン
  - ひとりモード：「この言葉にする」1ボタン
- 「戻る」（比較画面へ）

**ユーザー操作 → 状態遷移**
- 候補またはセレクトで時間を選ぶ → `choose-clarify-seconds` → プレビュー更新、確認エリア表示（確認状態はリセット）
- ふたりモード：「Aさん OK」「Bさん OK」→ `confirm` → 両方そろうと完了画面。押したボタンは「Aさん OK 済み」に変わる。
- 「変えたい」→ `request-change` → 時間未選択に戻る
- ひとりモード：「この言葉にする」→ `confirm`（A）→ 完了画面
- 戻る → 比較画面（選択はリセット）

**入力エラーへの対応**
- 時間未選択では確認ボタンを表示しない（押せない）。
- 自動で時間を決定しない。候補はあくまで手がかりで、最初はどれも選ばれていない。

**スマートフォン**
- 候補ボタンは縦に並べ、全幅。
- 確認ボタンは画面下部に横並び（A・B）で、それぞれ十分な幅を取る。

**アクセシビリティ**
- 候補ボタン群は `role="radiogroup"` 相当（ネイティブのラジオボタンをボタン風に表示するのが望ましい）。
- プレビュー文は `aria-live="polite"`。
- 確認ボタンは押下状態を `aria-pressed` で示す。

**30秒デモ**：25〜30秒。「共通範囲の終わり」がない（gap）場合でも、「あなたの範囲の終わり：5分」と「ソラの範囲の終わり：30分」を見比べ、「10分」を選んで「10分以内に行くね」を完成させる。

## 6. 完了画面（`done`）

**目的**：作った言葉を確認し、体験を締めくくる。

**表示情報**
- 見出し「言葉ができました」
- 完成した文（大きく）：「10分以内に行くね」
- 元の言葉との対比：「すぐ行く」→「10分以内に行くね」
- 2人の範囲（文章で）
- ふたりモード：「Aさん・Bさんが確認しました」
- ひとりモード：「今回の相手は架空のサンプルです。本当の相手と使うときは、相手にも確認しよう。」
- 締めの一言：「曖昧な言葉が悪いわけではありません。大事なときは、具体的に言ってみよう。」

**UI 要素**
- 主ボタン「もう一度やる」→ `reset` → スタート
- 補助ボタン「ほかの言葉でくらべる」→ `choose-another` → 同じモードのまま選択画面

**入力エラー**：なし。
