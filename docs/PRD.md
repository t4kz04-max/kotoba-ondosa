# PRD.md

# 言葉の温度差：プロダクト要求仕様書

副題：同じ言葉なのに、同じ意味じゃない。

関連文書：[PROJECT_OVERVIEW.md](PROJECT_OVERVIEW.md) / [UX_SPEC.md](UX_SPEC.md) / [DOMAIN_SPEC.md](DOMAIN_SPEC.md) / [TECH_SPEC.md](TECH_SPEC.md) / [DEMO_SPEC.md](DEMO_SPEC.md)

## 1. プロダクトの目的

日常の曖昧な言葉（「すぐ行く」「ちょっと待って」「あとでやる」）について、人によって思い浮かべる時間が違うことを **体験として発見** してもらう。そのうえで、相手と共有できる **具体的な言葉に言い換える** ところまでを、一続きの体験として提供する。

最重要の体験：

**自分の感覚を入力 → 相手の感覚を知る → 違いに驚く → 具体的な言葉に変える**

## 2. 解決する課題

- 曖昧な言葉は便利だが、話し手と聞き手が思い浮かべる時間は一致しているとは限らない。
- その違いは普段は目に見えないため、違いがあること自体に気づきにくい。
- 違いに気づいても、どう言い換えればよいかのきっかけがない。

本作品は「誰が正しいか」を判定しない。違いを見える形にし、言い換えのきっかけをつくる。

## 3. 対象ユーザー

| ユーザー | 状況 | 必要なこと |
|---|---|---|
| 中学生（主対象） | 友だち・家族と一緒に、または1人で試す | 説明を読まずに操作できる。スマートフォンで使える |
| 家族・友人 | 中学生と一緒に試す | ふたりモードで、相手の回答を見ずに入力できる |
| コンテスト審査員・来場者 | 初見で短時間触る | 30秒程度で価値が分かる。ひとりでも体験が成立する |
| 学校関係者 | 授業・説明で使う | 結果が個人の評価にならない。個人情報を取らない |

## 4. 独自性（単なるアンケートではない理由）

| 一般的なアンケート | 言葉の温度差 |
|---|---|
| 多数の回答を集計し、平均や割合を示す | **2人の回答を同じ時間軸に重ね**、共通範囲と違いを示す |
| 1つの値を答える | **範囲**（早くて〜遅くて）で答える。人の感覚の幅そのものを扱う |
| 回答して終わり | 違いを見た後に **具体的な言葉に言い換え、双方が確認する** ところまで進む |
| 多数派が「答え」に見える | どちらも正解としない。判定・スコアを出さない |
| 回答が誰かに見える／保存される | 1台の端末で **相手の回答を見ずに入力** する画面遷移。データを保存しない |

技術的な独自性：

- 区間の関係（一致・包含・重なり・接触・離れ）を数学的に分類し、境界条件まで定義した比較ロジック（DOMAIN_SPEC §5）
- 秒〜時間を1本の軸に収める非線形（区分線形）時間軸の SVG 可視化（DOMAIN_SPEC §8）
- 評価語を含まない、関係に応じた説明文の自動生成（DOMAIN_SPEC §9.2）
- 比較結果から「話し合いの手がかり」を生成し、人が選ぶ具体化（DOMAIN_SPEC §6）

## 5. 30秒で伝える価値

> 「あなたの『すぐ行く』は何分？」
> 答えて、相手と重ねたら、思っていた時間が違った。
> だから「10分以内に行くね」と言い換える。

- 0〜5秒：問いを見る（説明文は1行）
- 5〜15秒：スライダーで範囲を答える
- 15〜25秒：相手（またはサンプル）と重ねた結果を見る
- 25〜30秒：具体的な言葉が完成する

詳細は [DEMO_SPEC.md](DEMO_SPEC.md)。

## 6. メインユーザーフロー

```
スタート（モード選択）
  └→ 言葉・場面の選択
       └→ 感覚入力（あなた／Aさん）
            ├─[ひとり]→ 比較結果（vs 架空サンプル）
            └─[ふたり]→ 交代画面 → 感覚入力（Bさん）→ 公開前画面 → 比較結果
                                                               └→ 言葉の具体化（＋双方の確認）
                                                                    └→ 完了 → スタート
```

画面ごとの詳細は [UX_SPEC.md](UX_SPEC.md)、状態遷移は [DOMAIN_SPEC.md](DOMAIN_SPEC.md) §7。

## 7. ひとりモード

- 目的：相手がいなくても「違いに驚く」体験を成立させる。展示会場で1人で触る来場者にも対応する。
- 比較相手：言葉ごとに3件の **架空のサンプル回答**。性格の異なる架空の人物として表示する（例：「サンプル：ソラ（架空）」）。
- サンプルは自分の回答を入力した **後** にだけ表示する（先に見せると回答が引きずられるため）。
- 比較画面でサンプルを切り替えられる。最初に表示するサンプルは固定（データ順の先頭）。
- サンプルを集計しない。「みんなの平均」「多くの人は」などの表示をしない。
- 「架空の回答であり、実際の調査結果ではない」ことを、比較画面に常に表示する。
- 具体化では、相手が架空のため自分だけで確認して完了する。完了画面で「本当の相手と使うときは相手にも確認しよう」と促す。

## 8. ふたりモード

- 目的：身近な2人が、1台の端末で互いの感覚の違いを発見する。
- 1台の端末を交互に使う。A が入力 → 交代画面 → B が入力 → 公開前画面 → 2人で結果を見る。
- B の入力中、A の回答は画面にも操作でも見えない（戻る操作で A の入力画面に戻れない）。
- 2人とも入力した後、「2人で画面を見てね」画面で、2人がそろってから結果を開く。
- 具体化の最後に、A と B がそれぞれ「OK」を押して確認する。
- 名前の入力は求めない（「Aさん」「Bさん」と表示）。名前入力は拡張機能とする。

## 9. 必須機能（MVP：Phase 3）

| ID | 機能 | 概要 |
|---|---|---|
| F1 | モード選択 | スタート画面で「ひとりで試す」「ふたりで試す」を選ぶ |
| F2 | 言葉・場面の選択 | 3語（すぐ行く／ちょっと待って／あとでやる）から選ぶ。各語に場面・起点・終点を表示 |
| F3 | 感覚入力 | 「早くて」「遅くて」の2つのスライダーで時間範囲を入力する |
| F4 | ひとりモード | 架空サンプルとの比較。切り替え可能。架空表示 |
| F5 | ふたりモード | 交代画面・公開前画面を挟んだ交互入力 |
| F6 | 比較結果 | 同じ時間軸に2つの範囲を表示し、共通範囲・空白を示す。関係の説明文、共通範囲、空白、中心値の差を表示 |
| F7 | 言葉の具体化 | 手がかり（候補）を示し、人が時間を選んで具体的な文を作る |
| F8 | 双方の確認 | ふたりモードでは A・B がそれぞれ確認する |
| F9 | 完了 | 完成した文を表示し、最初に戻れる |
| F10 | 最初から | どの画面からでも最初に戻れる（確認ダイアログあり） |
| F11 | レスポンシブ | 幅 320px 以上のスマートフォン〜PCで操作できる |

## 11. 非対象機能（作らないもの）

- 誤解率・すれ違い率・相性スコア・一致度（%）の算出と表示
- どちらの解釈が正しいかの判定、「普通はこう」という基準の提示
- 回答のサーバー送信、データベース、アカウント・認証
- 外部 AI API による文章生成
- 実在の調査データ・統計としてのサンプル提示
- 回答の永続保存（localStorage を含む。MVP では保存しない）
- 時間以外の曖昧さ（量・程度など）の比較

## 12. 機能別の受け入れ基準

| ID | 受け入れ基準 |
|---|---|
| F1 | スタート画面から1タップでどちらのモードも開始できる。説明文は3行以内 |
| F2 | 3語すべてで、言葉・場面・起点・終点が表示される。選ぶと入力画面に進む |
| F3 | 早くて ≤ 遅くて が常に保たれ、不正な範囲を送信できない。キーボード（矢印キー）でも操作できる。値は「5分」のように読める形で表示され、スクリーンリーダーでも読み上げられる。0 を含む範囲、幅0の範囲（早くて＝遅くて）を入力できる |
| F4 | 自分の入力前にサンプルの値は表示されない。比較画面に架空である旨が常に表示される。3件のサンプルを切り替えられ、切り替えると図と説明文が更新される。集計値は表示されない |
| F5 | B の入力中・交代画面・公開前画面に A の回答が一切表示されない。B の入力画面から「戻る」で A の入力画面に戻れない。公開前画面で操作するまで結果は表示されない |
| F6 | 2つの範囲が同じ軸に、色以外の手段（ラベル・模様）でも区別して表示される。共通範囲があれば強調され、なければ空白が示される。DOMAIN_SPEC §5.5 の全境界ケースで正しい関係・説明文が表示される。評価語・スコアが表示されない |
| F7 | 初期状態で時間は未選択。候補は DOMAIN_SPEC §6.2 の規則で生成され、候補以外の時間も選べる。時間を選ぶと文（例：「10分以内に行くね」）がすぐに表示される。時間未選択では確認に進めない |
| F8 | ふたりモードでは A・B の両方の確認がそろうまで完了しない。「変えたい」で時間の選択に戻れる。ひとりモードでは1回の確認で完了し、架空の相手である旨が表示される |
| F9 | 完成した文・言葉・2人の範囲が表示される。「もう一度」でスタートに戻り、前の回答は残らない |
| F10 | どの画面にも「最初から」があり、確認後に全状態がリセットされる |
| F11 | 幅 320px・375px・1280px で横スクロールが発生せず、主要操作のタップ領域が 44×44px 以上ある |
| 共通 | ドメインロジックの単体テストが成功する。型チェック・ビルドが成功する |

## 13. 想定される失敗パターンと対策

| 失敗パターン | 対策 |
|---|---|
| 範囲入力の意味が分からず、1点しか答えない | 「早くて」「遅くて」の2つのスライダーに分け、問いを「どのくらいなら『すぐ行く』だと思う？」とする。幅0も有効な回答として扱う |
| 正解があると思って身構える | スタート画面とプロンプトで「正解はありません」と伝える。評価語を出さない |
| ふたりモードで先の回答が見える | 交代画面・公開前画面、戻る操作の制限（F5） |
| 比較結果が「点数」に見える | スコア・%を表示しない。説明文は事実のみ |
| 架空サンプルを統計だと誤解する | 「（架空）」表記と注記を常時表示。集計しない |
| 非線形軸を線形だと誤読する | 目盛りに必ず時間ラベルを付ける。「目盛りの間隔は等しくありません」と注記する |
| 結果を見て終わり、具体化に進まない | 比較画面の主ボタンを「具体的な言葉にする」にする |
| 具体化で何を選べばいいか分からない | 2人の範囲の終わり・共通範囲の終わりを候補として提示する |
| スマートフォンでスライダーが操作しにくい | スライダーを画面幅いっぱいにし、つまみを大きくする。矢印ボタン（−／＋）も併設する |
| 途中で離脱し、次の来場者が途中画面から始める | 常設の「最初から」。自動リセットは拡張機能 X8 |
| 説明文が一方を責めるように読める | DOMAIN_SPEC §9.2 の生成ルールと禁止語テスト |

## 14. 完成の定義

MVP（Phase 3 完了時）は次をすべて満たしたときに完成とする。

1. ひとりモード・ふたりモードの両方で、スタートから完了まで操作できる。
2. 3語すべてで比較と具体化ができる。
3. 機能別の受け入れ基準（§12）をすべて満たす。
4. ドメインロジックの単体テスト（DOMAIN_SPEC §11）が成功する。
5. `npm run typecheck`・`npm run test`・`npm run build` が成功する。
6. 回答データを外部に送信・保存しない。
7. 架空のサンプルが架空であることが明示されている。

作品全体（Phase 8 完了時）の完成は ROADMAP.md の各 Phase の完了条件に従う。

## 15. 要確認事項（人間の意思決定が必要）

各文書で「要確認事項 D-n」と参照している項目。推奨案で仕様を書いているが、変更する場合は該当文書を更新する。

| ID | 論点 | 推奨案（現在の仕様） | 主な代替案 | 推奨理由 |
|---|---|---|---|---|
| D-1 | 時間軸の形 | 言葉ごとの11点の目盛りを等間隔に並べた **非線形軸** | 線形軸 | 「10秒と1分」「1時間と6時間」を同じ図で見分けられる。線形だと短い範囲が潰れる。代わりに「間隔は等しくない」注記が必要 |
| D-2 | 3語の場面・起点・終点 | DOMAIN_SPEC §2.2 の通り（特に「あとでやる」は **始める** 時点） | 「終わる」時点、別の場面 | 宿題の量という別要因を混ぜないため |
| D-3 | 最大値 | すぐ行く60分／ちょっと待って30分／あとでやる12時間。超える選択肢は設けない | 「それ以上」選択肢を追加 | 計算と図が単純になる。「それ以上」は区間の上限が無限になり比較が定義しにくい |
| D-4 | 入力方法と初期値 | 「早くて」「遅くて」の2スライダー、初期値は全範囲 | 1本の2つまみスライダー、初期値を中間に | ネイティブ部品でアクセシビリティが高い。中間の初期値は回答を引きずる |
| D-5 | ひとりモードのサンプル | 架空の3人（ソラ・ミナト・ヒカリ）を切り替え。最初はソラ | 1人だけ、ランダム表示 | 1人だと「その人が基準」に見えやすい。ランダムはデモの再現性が下がる |
| D-6 | 中心値の扱い | 文章で「範囲のまんなかは◯分ちがう」とだけ示し、図には描かない | 図に中心マーカーを描く、中心値を表示しない | 非線形軸では見た目の中心と一致せず誤読を招く。一方で「早め／遅め寄り」の目安として文章では有用 |
| D-7 | 具体化の形 | 言葉ごとの固定文型（「{time}以内に行くね」など）＋時間の選択。自由記述なし | 自由記述、複数の文型から選ぶ | 30秒で完了でき、入力内容に個人情報が入らない |
| D-8 | 具体化の候補 | 各範囲の終わり・共通範囲の終わりのみ。「間をとる」案は出さない | 中間値を候補に加える | アプリが妥協点を提案すると「決定」に見えるため。人が話し合う余地を残す |
| D-9 | 名前入力 | MVP では入力なし（Aさん／Bさん） | 任意のニックネーム | 30秒体験の手数を減らし、個人情報を扱わない |
| D-10 | データ保存 | 一切保存しない | localStorage に履歴保存 | 展示端末で前の人の回答が残らない。プライバシー説明が簡単 |
| D-11 | 言葉の数 | MVP は3語・各1場面 | 語や場面を増やす | まず3語で中心体験を完成させる。場面違いは拡張 X1 |
| D-12 | 比較画面からの戻る | 設けない（やり直しは「最初から」） | 入力画面へ戻れる | ふたりモードで結果を見た後の再入力は、相手の回答を知った上での入力になるため |
