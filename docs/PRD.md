# 言葉の温度差：プロダクト要求仕様書

副題：同じ言葉なのに、同じ意味じゃない。

関連文書：[PROJECT_OVERVIEW.md](PROJECT_OVERVIEW.md) / [UX_SPEC.md](UX_SPEC.md) / [DOMAIN_SPEC.md](DOMAIN_SPEC.md) / [TECH_SPEC.md](TECH_SPEC.md) / [DEMO_SPEC.md](DEMO_SPEC.md)

## 1. プロダクトの目的

日常の曖昧な言葉（「すぐ行く」「ちょっと待って」「あとでやる」）について、人によって思い浮かべる時間が違うことを **体験として発見** してもらう。そのうえで、相手と共有できる **具体的な言葉に言い換える** ところまでを、一続きの体験として提供する。

最重要の体験：

**自分の感覚を入力 → 相手の感覚を知る → 違いに驚く → 具体的な言葉に変える**

## 2. 解決する課題

- 曖昧な言葉は便利だが、話し手と聞き手が思い浮かべる時間は一致しているとは限らない。
- その違いは普段は目に見えないため、違いがあること自体に気づきにくい。
- 違いに気づいても、どう言い換えればよいかのきっかけがない。

本作品は「誰が正しいか」を判定しない。違いを見える形にし、言い換えのきっかけをつくる。

## 3. 対象ユーザー

| ユーザー | 状況 | 必要なこと |
|---|---|---|
| 中学生（主対象） | 友だち・家族と一緒に、または1人で試す | 説明を読まずに操作できる。スマートフォンで使える |
| 家族・友人 | 中学生と一緒に試す | ふたりモードで、相手の回答を見ずに入力できる |
| コンテスト審査員・来場者 | 初見で短時間触る | 30秒程度で価値が分かる。ひとりでも体験が成立する |
| 学校関係者 | 授業・説明で使う | 結果が個人の評価にならない。個人情報を取らない |

## 4. 独自性（単なるアンケートではない理由）

| 一般的なアンケート | 言葉の温度差 |
|---|---|
| 多数の回答を集計し、平均や割合を示す | **2人の回答を同じ時間軸に重ね**、共通範囲と違いを示す |
| 1つの値を答える | **範囲**（早くて〜遅くて）で答える。人の感覚の幅そのものを扱う |
| 回答して終わり | 違いを見た後に **具体的な言葉に言い換え、双方が確認する** ところまで進む |
| 多数派が「答え」に見える | どちらも正解としない。判定・スコアを出さない |
| 回答が誰かに見える／保存される | 1台の端末で **相手の回答を見ずに入力** する画面遷移。データを保存しない |

技術的な独自性：

- 区間の関係（一致・包含・重なり・接触・離れ）を数学的に分類し、境界条件まで定義した比較ロジック（DOMAIN_SPEC §5）
- 経過時間に比例する線形時間軸の SVG 可視化。全体表示と、A・B の範囲が収まる拡大表示を切り替えられる（DOMAIN_SPEC §6）
- 評価語を含まない、関係に応じた説明文の自動生成（DOMAIN_SPEC §9.2）
- 比較結果から「話し合いの手がかり」を生成し、人が選び、実行できるか確かめて承認する具体化（DOMAIN_SPEC §7）
- 相手の回答を UI に渡さない、純粋関数による画面遷移の管理（DOMAIN_SPEC §8）

## 5. 30秒で伝える価値

> 「あなたの『すぐ行く』は何分？」
> 答えて、相手と重ねたら、思っていた時間が違った。
> だから「10分以内に着くね」と言い換える。

- 0〜5秒：問いを見る（説明文は1行）
- 5〜15秒：スライダーで範囲を答える
- 15〜25秒：相手（またはサンプル）と重ねた結果を見る
- 25〜30秒：具体的な言葉が完成する

詳細は [DEMO_SPEC.md](DEMO_SPEC.md)。

## 6. メインユーザーフロー

```
スタート（モード選択）
  └→ 言葉・場面の選択
       └→ 感覚入力（あなた／Aさん）
            ├─[ひとり]→ 比較結果（vs 架空サンプル）
            └─[ふたり]→ 交代画面 → 感覚入力（Bさん）→ 公開前画面 → 比較結果
                                                               └→ 言葉の具体化（時間を選ぶ → 実行できるか確認 → 承認）
                                                                    └→ 完了 → スタート
```

画面ごとの詳細は [UX_SPEC.md](UX_SPEC.md)、状態遷移は [DOMAIN_SPEC.md](DOMAIN_SPEC.md) §8。

## 7. ひとりモード

- 目的：相手がいなくても「違いに驚く」体験を成立させる。展示会場で1人で触る来場者にも対応する。
- 比較相手：言葉ごとに3件の **架空のサンプル回答**。性格の異なる架空の人物として表示する（例：「サンプル：ソラ（架空）」）。
- サンプルは自分の回答を入力した **後** にだけ表示する（先に見せると回答が引きずられるため）。
- 比較画面でサンプルを切り替えられる。最初に表示するサンプルは固定（データ順の先頭）。
- サンプルを集計しない。「みんなの平均」「多くの人は」などの表示をしない。
- 「架空の回答であり、実際の調査結果ではない」ことを、比較画面に常に表示する。
- 具体化では、相手が架空のため自分だけで確認して完了する。完了画面で「本当の相手と使うときは相手にも確認しよう」と促す。

## 8. ふたりモード

- 目的：身近な2人が、1台の端末で互いの感覚の違いを発見する。
- 1台の端末を交互に使う。A が入力 → 交代画面 → B が入力 → 公開前画面 → 2人で結果を見る。
- B の入力中、A の回答は画面にも操作でも見えない（戻る操作で A の入力画面に戻れない）。
- 2人とも入力した後、「2人で画面を見てね」画面で、2人がそろってから結果を開く。
- 具体化の最後に、A と B がそれぞれ「その時間で実際にできる／待てる」ことを確認してから「OK」を押す。
- 名前の入力は求めない（「Aさん」「Bさん」と表示）。名前入力は拡張機能とする。

## 11. 非対象機能（作らないもの）

- 誤解率・すれ違い率・相性スコア・一致度（%）の算出と表示
- どちらの解釈が正しいかの判定、「普通はこう」という基準の提示
- 回答のサーバー送信、データベース、アカウント・認証
- 外部 AI API による文章生成
- 実在の調査データ・統計としてのサンプル提示
- 回答の永続保存（localStorage を含む。MVP では保存しない）
- 時間以外の曖昧さ（量・程度など）の比較

## 13. 想定される失敗パターンと対策

| 失敗パターン | 対策 |
|---|---|
| 範囲入力の意味が分からず、1点しか答えない | 「早くて」「遅くて」の2つの入力に分け、問いを「どのくらいなら『すぐ行く』だと思う？」とする。長さ0も有効な回答として扱う |
| スライダーの初期位置のまま決定してしまう | 初期状態を未入力とし、両端を操作・入力するまで確定できないようにする |
| 正解があると思って身構える | スタート画面とプロンプトで「正解はありません」と伝える。評価語を出さない |
| ふたりモードで先の回答が見える | 交代画面・公開前画面、戻る操作の制限（F5） |
| 比較結果が「点数」に見える | スコア・%を表示しない。説明文は事実のみ |
| 架空サンプルを統計だと誤解する | 「（架空）」表記と注記を常時表示。集計しない |
| 線形軸で短い範囲（例：10秒〜30秒）が見えにくい | 最小描画幅で幅を不正確に広げることはしない。A・B の範囲が収まる「拡大表示」を用意し（線形性は維持）、範囲の文章表示で正確な値を必ず示す |
| 上限（例：60分）を言葉の意味の上限だと受け取る | 入力画面に「60分より長いと感じる人もいます」と明記する |
| 具体化の候補を「守れる約束」と受け取る | 候補を「解釈からの手がかり」と表示し、実行できるかの確認を承認の条件にする |
| 結果を見て終わり、具体化に進まない | 比較画面の主ボタンを「具体的な言葉にする」にする |
| 具体化で何を選べばいいか分からない | 2人の範囲の終わり・共通範囲の終わりを候補として提示する |
| スマートフォンでスライダーが操作しにくい | スライダーを画面幅いっぱいにし、つまみを大きくする。数値入力を併設する |
| 途中で離脱し、次の来場者が途中画面から始める | 常設の「最初から」。自動リセットは拡張機能 X8 |
| 説明文が一方を責めるように読める | DOMAIN_SPEC §9.2 の生成ルールと禁止語テスト |

## 14. 完成の定義

MVP（Phase 3 完了時）は次をすべて満たしたときに完成とする。

1. ひとりモード・ふたりモードの両方で、スタートから完了まで操作できる。
2. 3語すべてで比較と具体化ができる。
3. 機能別の受け入れ基準（§12）をすべて満たす。
4. ドメインロジックの単体テスト（DOMAIN_SPEC §11）が成功する。
5. `npm run typecheck`・`npm run test`・`npm run build` が成功する。
6. 回答データを外部に送信・保存しない。
7. 架空のサンプルが架空であることが明示されている。

作品全体（Phase 8 完了時）の完成は ROADMAP.md の各 Phase の完了条件に従う。

### 残っている未確定事項

現時点で、プロダクトの意味や中心体験に関わる未確定事項はない。次は Phase 3 以降に決める。

- 入力が未入力であることを示すスライダーの見た目（Phase 4〜5。MVP ではつまみを薄く表示し「未選択」と表記）

### Phase 3 で確定した実装上の選択

- 線形軸の短い範囲：最小描画幅は採用せず、「全体表示」と「拡大表示」（A・B の範囲が収まる表示範囲）を切り替える。拡大中は表示範囲を文章で明記する。
- 範囲入力：「早くて」「遅くて」は独立して操作し、逆転は自動修正せずエラーとして理由を表示する。スライダーは刻みで大まかに、数値入力で正確に調整する。
- 完了画面の見出しは「ことばが、約束になった。」。完成した文のコピー機能を付ける（クリップボードのみ、保存はしない）。

## 15b. 具体化と確認の強化（Phase 6B）

- **具体化の目的**：違いに気づいたあと、「いつまでに」「何をするか」が伝わる文に言い換える。比較で答えた範囲（感じ方）と、実際にできるか（実行可能性）は別のものとして扱う。
- **完成文の意味**：完成文はシナリオの終点と同じ時点を「◯以内」で表す（すぐ行く＝着く、ちょっと待って＝そっちへ行く、あとでやる＝宿題を始める）。時間は起点から数える。文例はシナリオ定義から生成する（DOMAIN_SPEC §7.4）。
- **双方確認の条件**：ふたりモードでは A・B が **同じ完成文** をそれぞれ確認したときだけ完了し、「ことばが、約束になった。」と表示する。確認は取り消せる。時間を変えると全員の確認がリセットされる。片方だけでは完了しない。
- **ひとりモード**：確認するのは本人だけ。完了画面は「具体的な言い方を考えられた。」とし、架空の相手が了承したようには表示しない。
- 「場面を変えて比べる」には具体化を追加しない（結果画面に「場面が変われば、具体的に伝える内容も変わります」の一文だけを加えた）。

## 16. 場面を変えて比べる（Phase 6A）

### 目的

これまでの体験は「**人によって**同じ言葉の解釈が違う」ことを見せる。この体験では「**同じ人でも、場面が変わると**同じ言葉の解釈が変わることがある」ことを、自分の回答で確かめてもらう（拡張機能 X1 の具体化）。
場面によって必ず変わるとは言わない。変わらなかった場合は「同じでした」と伝える。

問いかけ：「あなたの『すぐ』は、いつも同じ？」

### 内容

- 1人で、「すぐ」を使う3つの場面に、それぞれ時間の範囲（早くて〜遅くて）を答える。
  1. 友だちに「すぐ行く」と伝える
  2. メッセージに「すぐ返信する」と伝える
  3. 宿題を「すぐ始める」と伝える
- 3場面とも、起点は「その言葉を伝えた瞬間」、終点は「その行動を始める瞬間」、上限は30分（比較のための範囲で、言葉の意味の上限ではない）。
- 3つの回答を同じ線形の時間軸に並べ、3つすべてに共通する時間（あれば）と、計算した事実だけの説明を表示する。
- 「もう一度試す」「スタートに戻る」。

### 既存モードとの違い

| | ひとり・ふたりモード | 場面を変えて比べる |
|---|---|---|
| くらべるもの | 2人（またはあなたと架空のサンプル）の解釈 | 同じ人の、3つの場面での解釈 |
| 言葉 | すぐ行く／ちょっと待って／あとでやる | 「すぐ」（3つの使い方） |
| 終点・上限 | 言葉ごとに違う（すぐ行くは「友だちが着く」・60分） | 3場面とも「行動を始める」・30分 |
| 具体化・双方の確認 | あり | なし（発見までで終える） |
| 架空のサンプル | ひとりモードで使う | 使わない |
| 状態 | `SessionState` | 独立した `ContextState` |

既存の「すぐ行く」（友だちが着くまで・60分）とは測るものが違うため、この体験のための場面データを別に定義した（DOMAIN_SPEC §12）。

### 受け入れ基準（F12）

- スタート画面から1タップで始められる。最初は未回答で、3場面とも既存と同じ入力検証（未入力・数字以外・負・上限超過・逆転を確定できない）。0分と長さ0を入力できる。
- ほかの場面の回答は入力中に表示しない。前の場面に戻ると、その場面の回答が入力欄に戻る。
- 結果では、3つの範囲を同じ線形の軸に色以外（丸数字・線種）でも区別して表示する。共通部分は帯、1点だけなら縦線、なければ「なし」。長さ0の範囲は点。
- 3つが完全に一致したときだけ「同じでした」と表示し、違いがあるとは表示しない。共通部分があることと、一致していることを区別する。
- 性格・正しさ・誤解の起きやすさ・統計に見える表示をしない。
- 既存のひとり・ふたりモードの動作を変えない。
