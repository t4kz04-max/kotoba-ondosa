# 言葉の温度差：UI デザイン仕様（Phase 5A）

コンセプト：**親しみやすいコミュニケーション体験 × 正確で美しいデータ可視化**

この文書は Phase 5A で実装した見た目・演出の仕様を定める。情報設計と操作は [UX_SPEC.md](UX_SPEC.md)、計算は [DOMAIN_SPEC.md](DOMAIN_SPEC.md)、実装の構成は [TECH_SPEC.md](TECH_SPEC.md) に従う。

## 1. 配色

色はすべて `:root` の CSS 変数で定義する。SVG も `fill="var(--chart-a)"` のように同じ変数を参照する。

| 用途 | 変数 | 値 | コントラスト（実測） |
|---|---|---|---|
| 背景（アイボリー） | `--color-bg` | `#FAF9F5` | — |
| カード | `--color-surface` | `#FFFFFF` | — |
| 補助面（トラック・注記） | `--color-surface-2` | `#F4F2EC` | — |
| 本文（濃紺） | `--color-text` | `#1E293B` | 背景に対して 13.9:1 |
| 補助文字 | `--color-muted` | `#556070` | 背景に対して 6.0:1 |
| 入力欄の枠 | `--color-border-strong` | `#8A8475` | 白に対して 3.7:1（非テキスト 3:1 以上） |
| 主ボタン | `--color-primary` | `#1E293B`（白文字 14.6:1） | — |
| A（あなた・Aさん）図形 | `--chart-a` | `#EA580C` | 白に対して 3.6:1（図形 3:1 以上） |
| A の文字 | `--color-a-text` / `--color-a-strong` | `#C2410C` / `#9A3412` | 白に対して 5.2:1 / 7.3:1 |
| B（Bさん・サンプル）図形 | `--chart-b` | `#2563EB` | 白に対して 5.2:1 |
| B の文字 | `--color-b-text` | `#1D4ED8` | 白に対して 6.7:1 |
| 共通部分 | `--chart-common` | `#059669` | 白に対して 3.8:1 |
| 共通部分の文字 | `--color-common-text` | `#047857` | 白に対して 5.5:1 |
| エラー | `--color-error` | `#B91C1C` | 白に対して 6.5:1 |

参考値からの調整：

- 補助文字 `#64748B` はアイボリー地で 4.52:1 と基準ぎりぎりのため `#556070` に濃くした。
- オレンジ `#F97316` は白地で 2.8:1 と図形の基準（3:1）にも届かないため、図形は `#EA580C`、文字は `#C2410C`／`#9A3412` に分けた。
- 主ボタンは A・B どちらの色にも寄せない濃紺にした（どちらかの人を優先して見せないため）。

**色だけに依存しない区別**

| 対象 | 色以外の手段 |
|---|---|
| A と B | A は塗りつぶし、B は斜線。名前のラベルを各段に表示。事実の一覧・候補・確認欄では B の左線を破線にする |
| 共通部分 | 「共通 5分〜10分」の文字。1点の場合は縦線と丸 |
| 空白 | 両矢印と点線のガイド、「10分のひらき」の文字 |
| 選択中 | 「✓」と太い枠 |
| エラー | 「！」の付いた文、枠の色、`aria-invalid` |
| 未選択のスライダー | 点線の灰色のつまみと「未選択」の文字 |

## 2. タイポグラフィ

- 書体：`Hiragino Sans`, `Hiragino Kaku Gothic ProN`, `Noto Sans JP`, `Yu Gothic UI`, `Yu Gothic`, `Meiryo`, `system-ui`。**外部フォントは読み込まない**（TECH_SPEC §10：外部の読み込みなし・オフライン動作）。
- 基本：16px、行間 1.7。
- 見出しは `clamp()` で画面幅に合わせる。

| 要素 | 大きさ | 太さ |
|---|---|---|
| 作品名（スタート） | 2.3〜3.4rem | 900 |
| 問いかけ「あなたの「すぐ」は何分？」 | 1.4〜1.9rem | 900 |
| 画面の見出し `h1` | 1.45〜2rem | 800 |
| 比較結果の見出し | 1.5〜2.1rem | 900 |
| 入力画面の言葉 | 1.9〜2.6rem | 900 |
| 入力中の値（「5分」） | 1.75rem | 900 |
| 完成した言葉（完了画面） | 1.45〜2.6rem | 900（`text-wrap: balance`） |
| 図の文字（SVG） | 12〜13px | 700（白いふち付き） |

細い文字は使わない（本文 400、ラベル 700 以上）。

## 3. 余白

4px 単位の変数 `--space-1`〜`--space-7`（4・8・12・16・24・32・48px）。

- ページの左右：16px（600px 以上は 24px）。最大幅 46rem（736px）。
- 画面内の要素の間隔：16px（600px 以上は 24px）。
- カードの内側：16px（600px 以上は 24px）。

## 4. カード

- 白地、1px の枠 `#E6E2D8`、角丸 20px（大きいカードは 28px）、やわらかい影。
- **選べるカード**（モード・シナリオ・候補）は 2px の枠。ホバーで少し浮き、枠が濃くなる。右側に丸い矢印。
- **暗いカード**（公開前画面・完了画面）は濃紺のグラデーション。体験の「節目」だけに使う。
- **注記カード**（架空サンプルの注記）は点線の枠と補助面の色。

## 5. ボタン

| 種類 | 見た目 | 用途 |
|---|---|---|
| 主ボタン `button--primary` | 濃紺地・白文字・影 | 各画面で次へ進む操作（1画面に1つ目立たせる） |
| 公開ボタン `button--reveal` | 濃いオレンジ地・白文字 | 公開前画面の「2人の感覚を公開する」だけ |
| 補助ボタン `button--secondary` | 白地・濃い枠 | 戻る・ほかの言葉でくらべる・時間を選びなおす |
| 控えめなボタン `button--ghost` | 白地・薄い枠 | ヘッダーの「最初から」、「0分にする」 |
| 切り替え `segmented` | 補助面の中のボタン群、選択中は白地・枠・✓ | 全体表示／拡大表示、サンプルの切り替え |

- 高さは 44px 以上（大きいボタンは 56px）。
- 押せないとき（`disabled`）は補助面の色と補助文字の色にし、カーソルを変える。理由は近くの文で示す。

## 6. 各画面の構成

### スタート

1. ヒーローカード：バッジ「ことばの感覚をくらべる」→ 作品名 → 副題 → 小さな図 → 問いかけ「あなたの「すぐ」は何分？」→ 一言説明
2. 「はじめかたを選ぶ」：モードカード2枚（スマートフォンは縦、600px 以上は横並び）
3. 「回答はどこにも保存・送信されません。」

小さな図は「Aさんの「すぐ」」「Bさんの「すぐ」」の2本の帯がずれて並ぶ飾り（`aria-hidden`）。**数値・目盛りは入れない**（実在のデータに見えないようにするため）。

### シナリオ選択

カード3枚。各カードに：言葉（大きく）、場面、「はかる時間（起点ときから、終点まで）」「答える範囲（0〜上限）」。値は `src/data/scenarios.ts` の既存データをそのまま表示する。

### 入力

1. 番のバッジ（あなたの感覚／Aさんの番＝オレンジ、Bさんの番＝青）
2. 言葉（大きく）と、場面・問いのカード
3. 「早くて（範囲の始まり）」「遅くて（範囲の終わり）」を別々のカードに分ける。各カード：大きな現在値（未入力は「未選択」）→ スライダー → 0・上限の目盛り → 数値欄。「早くて」には「0分にする」ボタン
4. プレビューカード：範囲の文章（またはエラー）と、比較画面と同じ線形の時間軸。未入力のときは空の帯と「まだ範囲を選んでいません」
5. 上限の注記
6. 下部に固定された操作バー（スマートフォン）：「戻る」「これで決定」

### 交代・公開前（ふたりモード）

- 交代：白いカード。端末を渡すアイコン、「Aさんの回答を受け取りました」、見出し「Aさんの回答をかくしました」、主ボタン「Bさんです。はじめる」。回答は受け取らない。
- 公開前：暗いカード。A・B の丸、見出し「2人の答えがそろいました」、公開ボタン「2人の感覚を公開する」。**比較結果の公開演出の待機状態**を兼ねる（§7）。

### 比較結果（最重要）

上から：

1. 「「すぐ行く」をくらべる」
2. 見出し（`describeComparison` の headline）
3. 2人の回答のチップ（色見本・名前・範囲）
4. 図のカード：起点 → 終点、全体表示／拡大表示、**3層の図**、表示範囲の文、架空サンプルの注記（ひとりモード）
5. 説明カード：`details` の文と「数字でまとめて見る」（開閉。共通範囲・空白・中心値の差）
6. うながしと主ボタン「具体的な言葉にする」
7. サンプルの切り替え（ひとりモード）
8. 「ほかの言葉でくらべる」

**3層の図**（`TimelineChart` の `overlay`）

| 段 | 内容 |
|---|---|
| 1. A の段 | 名前（左）、範囲（右）、塗りつぶしの帯 |
| 2. B の段 | 名前（左）、範囲（右）、斜線の帯 |
| 3. 重ねると | A（半透明＋枠）と B（斜線）を同じ高さに重ね、共通部分を緑で塗る。右に「共通 5分〜10分」「共通 5分（1点だけ）」「10分のひらき」 |

- すべての段が **同じ線形スケール**（`createLinearScale`）で、重ね合わせの段の x 座標は上の2段とまったく同じ（`buildTimelineLayout` のテストで確認）。
- 共通部分は、段をまたぐ薄い緑の縦帯でも示す。
- 1点だけの接触は縦線と丸（幅を持たせない）。長さ0の範囲はひし形（幅を持たせない）。
- 空白は重ね合わせの段の両矢印と、上の段から下ろした点線のガイド。
- 最小描画幅は使わない。全体表示で 4px 未満の帯があれば拡大表示を案内する。

### 言葉の具体化

1. 見出し
2. 比較図（3層、演出なし）
3. 手がかりカード：注記 → （共通範囲がないときは「共通範囲からの手がかりはありません」）→ 候補カード → 「ほかの時間」
   - 候補は `agreementCandidates` の結果だけを表示する。根拠（basis）ごとに左線の色・模様と説明を変える
   - 「共通範囲の終わり」は共通範囲があるときだけ出る（basis が `end-of-intersection` のときだけ）
4. 文のカード：未選択は点線の枠と「時間を選ぶと、ここに言葉ができます。」、選択後は「「すぐ行く」を言いかえると」「「10分以内に行くね」」
5. 確認カード（時間を選んだ後だけ）：実行できるかの問い → 注記 → 確認する人ごとのカード（チェック＋OK）。承認済みは緑の「✓ Aさん：承認しました」。時間を変えるとカードごと作り直され、承認もチェックも消える
6. 「時間を選びなおす」「比較に戻る」「ほかの言葉でくらべる」

ひとりモードの確認カードは「実行できるかの確認」とし、「今回の相手は架空のサンプルなので、確認するのはあなただけです。」を表示する（架空のサンプルが同意したようには見せない）。

### 完了

1. 暗いカード：見出し「ことばが、約束になった。」→ 変化の枠「曖昧だった言葉」「「すぐ行く」」↓「（2人で／あなたが）具体化した言葉」「「10分以内に行くね」」→ 確認の文 → コピー
2. 2人の範囲のチップ
3. 締めの一言
4. 主ボタン「ほかの言葉でくらべる」、補助ボタン「最初から」

- 完成した言葉は黄色（`#FCD34D`、濃紺地で 11:1 以上）で最も大きく表示する。元の言葉には取り消し線を付けない（曖昧な言葉が悪いわけではないため）。
- ひとりモード：ラベルは「あなたが具体化した言葉」、注記「今回の相手は架空のサンプルです。この時間でできるか確かめたのは、あなただけです。本当の相手と使うときは、相手にも確認しよう。」。2人が合意したとは表示しない。

## 7. アニメーション

### 公開演出（比較結果）

ふたりモード：公開前画面（待機状態）→「2人の感覚を公開する」→ 比較結果画面で演出。
ひとりモード：「これで決定」の直後に比較結果画面で演出（待機のための操作は増やさない。自分の回答を決めた直後で、相手は架空のサンプルのため）。

| 順 | 内容 | 開始 | 長さ |
|---|---|---|---|
| 1 | 回答の公開：「〜をくらべる」と2人の回答チップ、各段の名前と範囲 | 0ms | 350ms（下からフェード） |
| 2 | A の帯が左端から伸びる → B の帯が伸びる（長さ0はその場に現れる） | 300ms／550ms | 500ms |
| 3 | 重ね合わせの段 → 共通部分／接点／空白の矢印 | 900ms／1100ms | 350〜400ms |
| 4 | 見出し・説明文・主ボタン | 1300ms | 400ms |

- 全体で約 1.7 秒。操作は演出中もできる。
- **伸びている途中の帯は一時的な表現**で、止まった状態の幅は線形スケールの値そのもの（固定の最小幅や誇張はない）。
- 内容は最初から DOM にあるため、スクリーンリーダーや演出を見ない人も同じ情報を得られる。見出しにはすぐフォーカスが移る。
- **くり返さない**：`useRevealOnce` が回答オブジェクトごとに1回だけ演出し、終了後（2秒）に演出用のクラスを外す。サンプル切り替え・表示範囲の切り替え・具体化画面から戻ったときは演出しない。新しく回答したときだけ再び演出する。
- 実装は CSS の `@keyframes` だけ（ライブラリなし）。

### その他

- ボタン・カードのホバー（150ms の色・位置の変化）。
- `prefers-reduced-motion: reduce` のときは、すべてのアニメーションと遷移を実質 0 秒にし、最初から最終状態を表示する。

## 8. レスポンシブ対応

- モバイルファースト。ブレークポイントは 600px の1つ。
- 確認した幅：320px・375px・768px・1280px（全画面で横スクロールなし）。
- 600px 未満：モードカードは縦、入力画面の「戻る／これで決定」は画面下に固定、事実の一覧は1列。
- 600px 以上：モードカード2列、事実の一覧2列、候補カード・確認カードは並べられるだけ並べる。
- 図は `useElementWidth` で実際の幅を測り、px 単位で描く（文字が小さくならない）。目盛りの数は幅から決める。
- 長い言葉は `overflow-wrap: anywhere` で折り返す。

## 9. アクセシビリティ

- 画面表示時に `h1` へフォーカス（既存の `useFocusHeading` を維持）。
- タップ領域 44×44px 以上（ボタン・数値欄・切り替え・チェック行・スライダーの高さ）。
- フォーカスは 3px の青い枠（`:focus-visible`）。
- ネイティブの `<input type="range">`・数値欄・チェックボックス・`<dialog>`・`<details>` を使う。
- エラーは文で示し、該当する欄に `aria-invalid`。メッセージは `aria-live` と `aria-describedby` で関連付ける。どの欄が問題かの判定にも `validateDraft` を使う。
- 図は `role="img"` と、見出し＋説明文の `aria-label`。同じ内容を文章でも表示する。
- 図の文字には白いふち（`paint-order: stroke`）を付け、線と重なっても読めるようにする。
- アイコンは装飾として `aria-hidden`。意味は必ず文字で伝える。

## 10. Gemini Canvas から採用した要素

- アイボリー背景・白いカード・オレンジと青のアクセント・濃紺の本文という配色の方向
- ロゴマーク「温」と作品名のヘッダー
- ヒーローカード（グラデーションの背景、バッジ、大きな作品名、2人のずれを示す小さなビジュアル）
- アイコン付きのモード選択カード
- 番を示す色付きのバッジ
- 比較結果の **3層構成**（A の段・B の段・重ね合わせの段）と、全体表示／拡大の切り替えボタンの見た目
- 公開前の待機カード（暗い背景・鍵や目のアイコン・公開ボタン）
- 候補カードと、双方の確認エリア（オレンジ系の枠のカード、人ごとのチェック）
- 完了画面の暗いカードと「曖昧だった言葉 ↓ 具体的な言葉」の対比、コピー・ほかの言葉でくらべる

## 11. Gemini Canvas から採用しなかった要素と理由

| 要素 | 理由 |
|---|---|
| Tailwind CDN・Google Fonts・Lucide（外部 CDN） | 外部の読み込みをしない方針（TECH_SPEC §10）とオフライン動作のため。素の CSS とインライン SVG で置き換えた |
| 帯の最小幅（`Math.max(…, 2)` ＝ 2%）、共通部分の最小幅 1.5% | 実際の長さより太く見せることになる。線形スケールのまま描き、長さ0は点、1点の接触は縦線で示す |
| 拡大表示の独自の範囲計算（×0.8・×1.2） | 既存の `computeZoomView`（テスト済み）を使う |
| 固定の初期回答（2分〜5分、10分〜20分）・初期の約束時間 | 初期値を回答にしない仕様（D-4）。未入力から始める |
| 固定の候補（「中間をとる」「確実に着く時間」など） | 候補は `agreementCandidates` から生成する（D-8：妥協点を自動で出さない） |
| シナリオの値・上限・刻み（あとでやるの 0.5時間刻みなど） | 既存の `scenarios.ts` を使う |
| 「温度差の分析レポート」「認識のズレ」「約 ◯分の隙間があります！」などの独自の説明文、人物の傾向の推測 | 説明文は `describeComparison` が事実だけで生成する。評価・推測をしない |
| 「おすすめ」「お手軽」のバッジ、「おすすめの約束時間候補」 | どちらかを推す表現を避ける |
| 2つのチェックボックスだけで確定する合意（ひとりモードでも B に「同意しました」） | 実行できるかの確認と人ごとの承認（F8）を維持。ひとりモードで架空の相手が同意したように見せない |
| 比較画面の「入力をやり直す」 | 比較結果から入力画面へは戻らない（D-12） |
| 公開前カードを比較画面の中に置く構成 | ふたりモードでは既存の公開前画面（`READY_TO_REVEAL`）を待機状態として使い、操作回数を増やさない。比較画面に入る前は回答を UI に渡さない設計も保つ |
| ヒーローの「Aさん：すぐ＝2分」などの数値入りの例 | 実在のデータに見えないよう、数値のない図にした |
| 浮遊・バウンドし続けるアニメーション | 注意をそらし、動きに敏感な人の負担になる。演出は公開の1回だけ |
| 「Communication Complete」などの英語ラベル、「温かなコミュニケーションが生まれました」 | 日本語で統一。結果を評価する言い方を避ける |
| 完了画面の「トップ画面（画面1）に戻る」の小さなリンク | 既存の「最初から」ボタン（44px 以上）を使う |
